# Testing

Use the Rust gates below for every broad validation pass.

```text
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all
cargo deny check
rayman context refresh
rayman gate status --check
rayman coverage status --check
rayman coverage status --format markdown --check --output docs/FEATURE_COVERAGE.md
cargo run -p rayman-cli --bin rayman -- docs maintain --check
cargo run -p rayman-cli --bin rayman -- docs compact-skill-rules --dry-run
cargo run -p rayman-cli --bin rayman -- assets status
cargo run -p rayman-cli --bin rayman -- assets scan
cargo run -p rayman-cli --bin rayman -- temp doctor
cargo run -p rayman-cli --bin rayman -- eval run --profile full
cargo run -p rayman-cli --bin rayman -- security audit
cargo run -p rayman-cli --bin rayman -- audit
cargo run -p rayman-cli --bin rayman -- benchmark run --smoke
rayman regression run --profile auto
rayman regression run --profile parallel-full
rayman release evidence --label local --no-write
```

Use `rayman gate status --check` as the broad readiness gate after a source refresh. It aggregates workspace-skill activation, Context Index freshness, Context OS state graph freshness, obsolete asset retirement, Codex host subagent ledger state, managed temp state, feature coverage, docs maintenance, cargo-deny dependency policy, security audit, repository audit, and no-write release evidence. The asset retirement check runs against the current workspace root for both opted-in customer workspaces and this RaymanCodingSkill repository, while keeping state in that workspace's `.RaymanCodingSkill/assets/retirement.json`. Goal/session success close has additional closure gates such as `req_id` evidence, pending work, active goals, manual/remote gaps, unresolved asset retirement, unresolved subagent ledger entries, stale Context OS state, and release/deploy `customer_deploy` readiness. Use `rayman regression run --profile quick` for a fast local smoke pass, `--profile full` for a serial broad pass, `--profile shared-parallel-full` for generic Cargo/Rust workspaces that should compile tests once and run compiled test executables with bounded workers from each Cargo package's manifest directory, `--profile auto` to select that shared-build strategy with a recorded decision for Cargo workspaces, and `--profile parallel-full` when broad regression should isolate Cargo-heavy checks in separate target directories to avoid lock contention. Every regression profile writes `.RaymanCodingSkill/regression/history.jsonl`, and all cargo steps use a TempManager-owned workspace-local `CARGO_TARGET_DIR` inside `.RaymanCodingSkill/tmp/runs/`. Successful runs delete the managed target run directory automatically; failed runs preserve it, mark the run failed, and print the retained path plus cleanup command for diagnosis.

## Coverage Expectations

Feature coverage is the machine-checkable source of truth for declared public functionality claims. `config/feature_coverage.yaml` maps each declared feature to documentation anchors, implementation anchors, semantic test anchors, validation commands, UI surfaces, validation records, and claim checks. Public commands, API endpoints, and declared claim checks must be listed in `test_anchors[].proves`; string-only anchors are not enough. `rayman coverage status --check` extracts current public CLI commands and API routes from source, enables strict validation, then hard-fails when a command/API surface is missing from the manifest, when a registered public surface lacks semantic test proof, when a declared claim check lacks implementation/test/validation anchors, or when an entry marked `strict_validation: true` lacks current passed `validation_records` with `updated_at`, `evidence_path`, exact command text, passed status, and configured `evidence_contains` text. It is not a natural-language theorem prover for arbitrary unregistered prose; new public docs, YAML runtime claims, and skill claims must be added to the manifest as claim checks before success. `rayman gate status --check` and `rayman audit` use the same strict gate for broad repository delivery. `docs/FEATURE_COVERAGE.md` is the human-readable matrix generated from the same manifest.

- Unit tests cover config dot-path get/set, auxiliary provider migration, provider order, timeout/proxy parsing, canonical AI-UBUNTU environment-proxy configuration, async reconciliation state, model routing fallback, auxiliary contribution event evidence, session pending state, workspace activation, backup safety, documentation size controls, lossless skill rule splitting, HTML developer-doc maintenance, customer project docs auto-completion, instruction lifecycle, multi-language project adapters, impact selection, regression risk recommendations, benchmark smoke, goal gates, quality incidents, quality pattern aggregation, hard quality gates, and CLI parsing.
- Project-understanding tests cover additive context protocol fields, Context OS state graph freshness, asset retirement exclusion from current evidence, stale Context Index required actions, stale-file close-gate messages, and `project_understanding_freshness` quality evidence.
